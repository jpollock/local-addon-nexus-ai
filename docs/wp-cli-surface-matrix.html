§1The findings that matter

The agent gap is discoverability, not capability

ssh_target is declared in no tool's inputSchema — but McpServer.ts:303 reads params.arguments and passes it through with no JSON-Schema validation and no stripping of unknown keys, and resolveTransport checks args.ssh_target first. An agent that already knows the parameter name can drive 14 tools against an external host today. It simply cannot discover that the parameter exists. Declaring it on 15 schemas is small, mechanical, and unlocks all 14 immediately.

External hosts already have the most permissive policy of the three

EXTERNAL_REMOTE_POLICY is blocklist-only by deliberate choice in Spec 1 — applying MCP's whitelist would have reproduced the five dead WPE tools on day one. So the restriction on external hosts is not policy, it is plumbing. The "policy fork" that opened this investigation does not exist.

A human at the CLI gets more on WP Engine than an agent does

The CLI's nexusWpCommand route applies a 4-item blocklist and no whitelist. The MCP route applies a 14-command whitelist, which is why five tools have remote paths that can never succeed. policy.ts:7 calls the divergence "real and load-bearing"; Spec 0 preserved it deliberately.

Four tools have no remote path at all

db export, import database, search replace and site health call resolveSite, not resolveTransport. search-replace against a remote host is domain migration and db export is how you get a backup off a VPS — arguably the two most valuable things to have on someone else's box. The CLI reaches them on WP Engine only through nexusWpCommand's arbitrary argv.

Three of 22, not four — and two failure modes worth knowing

wp health is wired to the MCP path, but wp_site_health is local-only and ignores ssh_target. Verified live: it fails with Site "undefined" not found. — and it fails because MCP is available; with MCP down it falls back to nexusWpCommand, which has no external branch either. Separately, nexusWpCommand on an ssh: target dies with Cannot read properties of undefined (reading 'split') — a raw TypeError, not a diagnosis. Also unrelated but real: wp health prints its error and exits 0.

§5The open question

Two problems of very different size:

  • Agents — declare ssh_target and wp_path on 15 tool schemas. Small, mechanical, unlocks 14 operations immediately. Worth doing regardless of the other half.
  • CLI — real plumbing. 19 of 22 commands route through nexusWpCommand, which has no external branch. Teaching it one requires deciding how to classify arbitrary argv as read or write, since resolveTransport needs an operation to run the environment gate.

Which baseline should external hosts target — the CLI's WP Engine behaviour (arbitrary WP-CLI with a blocklist, what a human gets today) or the tool set (structured, 14 operations, what an agent gets)?
