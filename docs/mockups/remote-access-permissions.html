What actually changes in code
1. Rename the section and the setting keys. The backend already uses remoteOperationPermissions / remoteSiteExceptions; Plan A renamed them and the UI never followed, so SettingsTab.tsx still writes wpeOperationPermissions and the gate survives only on a legacy fallback. Write the remote* keys and keep reading both, so existing installs migrate silently.
2. Mark the three WPE-only rows. Pull to local, Push to WPE and Delete / Promote have no external equivalent — an ssh: target only ever uses wpcli_read and wpcli. Dimming with a scope chip is honest without hiding settings that still matter for WP Engine. Hiding them entirely is the alternative; I'd rather not make a WPE-relevant control vanish.
3. Give exceptions a targetRef. This is the only functional bug. SettingsTab.tsx:231 writes { installName, environment, overrides } with no targetRef, and the matcher computes e.targetRef ?? `wpe:${e.installName}` — so a UI-created exception is always wpe:<name> and can never match ssh:<alias>. Today the per-target expanders are structurally WPE-only. Writing targetRef directly, and offering registered SSH aliases in the picker, fixes it; the matcher already honours it.
