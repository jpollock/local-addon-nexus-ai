## P2-1 — Move embeddings + vector store off the main thread

**Labels:** `performance` `high` · **Effort:** 1–2 wk · **The single biggest UX win.**

### Problem
`SqliteVecStore` is fully synchronous better-sqlite3 running in the Electron **main process** (the
`async` signatures are cosmetic; the `_concurrency=5` param is unused). At the measured **913 MB /
336-table** scale, one fleet-wide `searchAcrossSites` (a sequential exact-scan per site — sqlite-vec
0.1.x has no ANN index) **freezes the entire Local UI** — all IPC and renderer calls stall. Same
class for `upsert()` during indexing and `getAllDocuments()`.

### Fix
Move `SqliteVecStore` + `EmbeddingService` (the ONNX session) into an Electron `utilityProcess` (or
`worker_thread`) that owns the vectors.db handle, and talk to it over a message port — better-sqlite3
explicitly recommends worker threads for this. Cheaper interim mitigations if the full move slips:
honor the concurrency param (yield with `setImmediate` between sites), scope `searchAcrossSites` to
freshly-indexed sites, add a projection flag so callers that don't need embeddings don't materialize
them.

### Acceptance criteria
- [ ] A fleet-wide content search does not block the main thread (measure: renderer stays responsive
      during a search over the full vector set).
- [ ] Indexing a large site does not freeze the UI.
- [ ] No regression in search results vs. the current implementation (pin with a result-parity test).

## P2-2 — Delta indexing on site start; vectors.db orphan sweep + VACUUM

**Labels:** `performance` `high` · **Effort:** 2–3 d

### Problem
The default-on `siteStarted` hook calls `pipeline.indexSite` unconditionally and re-embeds **every
chunk** — no comparison against `post_modified_gmt`/`indexedAt`, though both columns exist and are
populated. On every start. Plus vectors.db grows monotonically: **no `VACUUM` anywhere**, `dropSite`
only frees pages to the freelist, and no sweep reconciles the 336 site table-sets against live sites
(measured ~913 MB, with tables for long-gone sites).

### Fix
1. Delta indexing: before embedding, query existing `post_modified_gmt`/`indexedAt` per post id and
   skip unchanged posts. The webhook path already does per-post incremental updates correctly, so
   full re-index on start is largely redundant for MU-plugin sites.
2. Startup/daily orphan sweep: `vectorStore.listSites()` minus the live site population → `dropSite`
   orphans; then `PRAGMA incremental_vacuum` / `VACUUM` (or `auto_vacuum=INCREMENTAL` at creation).
   Add vectors.db to the periodic WAL checkpoint (currently graph.db only), and wire
   `vectorStore.close()` (currently never called) into `before-quit` with a checkpoint.

### Acceptance criteria
- [ ] Starting a site with unchanged content re-embeds ~0 chunks (assert via the embed count).
- [ ] An orphan vector table (site removed) is swept on the next run; vectors.db size drops after
      `VACUUM`.
- [ ] vectors.db is checkpointed/closed cleanly on quit.

## P2-3 — Split the two god files; finish or delete the dead resolver split

**Labels:** `architecture` `high` · **Effort:** 3–5 d · **Unblocks P2-5 and future review.**

### Problem
`ipc-handlers.ts` (6,602 lines, `registerIpcHandlers` a single ~6,000-line function registering 135
channels) and `resolvers.ts` (6,259 lines, `createResolvers` a single function). Single-function god
files defeat review (diffs lack context), invite closure entanglement, and are **why the resolver
split stalled** — extracting from a 6,000-line closure is scary, so it half-happened, leaving
`resolvers/wpe.ts` + `sites.ts` + `twin.ts` (~2,000 LOC) maintained-in-sync with **zero production
callers**.

### Fix
1. Mechanical, behavior-preserving splits: group `safeHandle` registrations into per-domain register
   functions (`registerAgentIpc(deps)`, `registerFleetIpc(deps)`, …) — file moves, no logic change.
   Same for resolvers via the proven `createWpCliResolvers` spread pattern (`resolvers/wp-cli.ts` is
   the one live, already-extracted example).
2. Decide the dead split: **finish** it (extract each `wpe/sites/twin` domain and spread into
   `createResolvers`, deleting the god-file copy) or **delete** the dead copies and re-extract later.
   Do not leave the third state (maintained-but-unreferenced).

### Acceptance criteria
- [ ] `ipc-handlers.ts` and `resolvers.ts` each drop below ~1,500 lines, no behavior change (full
      suite green).
- [ ] No resolver domain exists in two places; `resolvers/wpe.ts|sites.ts|twin.ts` are either live
      (imported by `createResolvers`) or deleted.

## P2-4 — Pin `externalScoreable`; move duplicated rules into `src/common`

**Labels:** `architecture` `medium` · **Effort:** 1 d

### Problem
`externalScoreable = hasPlugins && !!row.php_version` is duplicated verbatim in `resolvers.ts:2944`
(GraphQL/CLI path) and `get-site-health.ts:91` (MCP path), pinned by **no test** — change one and the
CLI and MCP report different health for the same host. More broadly, several "duplicated because
main/renderer can't share a bundle" rules exist — but the premise is false (plain `tsc`, no bundler;
the renderer already runtime-imports values from `src/main`, and P0/P1 added shared pure modules to
`src/common`).

### Fix
1. Extract `externalScoreable` into one function both health paths import (put it in the shared
   health-calculator module), or at minimum add a shared-case-table pin test (the
   `effectiveCadence.test.ts` / `localDay.test.ts` pattern) covering both copies.
2. Sweep for other unpinned duplicated rules (the `indexRegistry` + `|| '8.0'` fallback lives in 3
   places per the review) and consolidate the pure ones into `src/common`, adding an ESLint
   `import/no-restricted-paths` rule to keep `src/common` free of Node/Electron imports.

### Acceptance criteria
- [ ] A shared test fails if the two `externalScoreable` copies diverge (or there is only one copy).
- [ ] The `|| '8.0'` php-version fabrication is removed from the WPE health path (pass `undefined`).

## P2-5 — Type the `NexusServices` seam

**Labels:** `architecture` `medium` · **Effort:** 2–3 d · **Eased by P2-3.**

### Problem
Two `NexusServices` interfaces exist (`src/main/types/nexus-services.ts` well-typed, 7 importers; and
`src/main/mcp/types.ts` `any`-riddled, 15 importers), and the mcp one declares 8 core services as
`any` (`graphService`, `eventProcessor`, `searchService`, `healthCalculator`, …). So `strict: true`
buys little across `src/main/mcp/**`. ~25 optional (`?:`) handles are consumed via `?.` — the exact
shape that once silently no-op'd every audit write for months (the `operationAuditLog` lesson).

### Fix
1. Merge to one interface (`mcp/types.ts` re-exports from `types/nexus-services.ts`); type the 8
   `any` fields from the real classes (most are already typed in the sibling interface).
2. Split into `CoreServices` (required, constructed together) vs. a narrow late-bound set, with a
   startup assertion that enumerates expected handles and logs loudly for any still-undefined after
   init — turning the silent-no-op class into a boot-time log line.

### Acceptance criteria
- [ ] One `NexusServices` interface; the 8 seam services are concretely typed; `any` count in
      `mcp/types.ts` → 0.
- [ ] A missing required service surfaces at startup, not as a silent `?.` no-op.

## P2-6 — Honest coverage baseline; triage the stale e2e tier

**Labels:** `testing` `medium` · **Effort:** 2–3 d · **Depends on P1-1.**

### Problem
`jest.config.js` sets a 80% `coverageThreshold` but has **no `collectCoverageFrom`**, so the
denominator is only files imported by tests — an untested whole file doesn't count. Real `src/main`
coverage is unknown. Separately, the e2e tier froze in March: ~30/33 files untouched through five
months of major change, and the documented skip policy used early `return` so a skipped test shows as
**passed**.

### Fix
1. Add `collectCoverageFrom: ['src/main/**/*.ts', 'src/cli/**/*.ts', 'src/common/**/*.ts']`, measure
   once for the honest baseline (expect a drop), then ratchet in CI rather than pinning a fictional
   80%. (CI now runs the full suite green — P1-1 — so this is measurable.)
2. e2e triage: run the March-era files once against the current app; delete or update the dead ones;
   reverse the skip policy so skipped shows as skipped with a printed reason. Promote the Dockerized
   SSH-fixture tests as the proof-of-concept for e2e-in-CI.

### Acceptance criteria
- [ ] `npm run test:coverage` reports real whole-tree coverage; the CI threshold reflects the
      measured baseline, not a decorative 80%.
- [ ] No e2e test can pass by silently skipping; the stale files are updated or removed.
