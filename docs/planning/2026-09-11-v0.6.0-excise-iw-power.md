# v0.6.0 Release Excision — IW + Power Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `main` publishable as v0.6.0 by removing every WP Engine Intelligent Web (IW) and WP Engine Power surface from the distributed artifact, and add a publish-time content guard so the removal cannot silently regress.

**Architecture:** Three phases in one branch. (1) A content assertion is added to the existing `prepublish-guard` and goes RED against today's `lib` — it is the mechanical completion test for everything after it. (2) IW is removed: 5 module files, 7 registered MCP tools, 3 IPC channels, 1 storage key, 1 shared type, and 2 renderer surfaces. (3) Power is removed: 3 implementation files, the gateway branch, 2 union/enum members in the shared type surface, and the connector picker's third option. The intelligence spine (`src/intelligence`, `src/main/intelligence-host`) is explicitly **retained** — it carries no WPE-internal product surface.

**Tech Stack:** TypeScript, Jest, Zod, React 16 (`React.createElement`, no JSX, no hooks), Electron main/renderer split, npm publish via `prepublishOnly`.

**Spec:** This document is self-contained; the scoping evidence is in the session that produced it. Baseline release under comparison is tag `v0.5.2` (2026-07-27, `53fec90f`).

## Global Constraints

- **Branch off `develop`, not `main`.** This repo adopted develop/main on
  2026-09-12: `develop` integrates, `main` is the released line (currently the
  `v0.5.2` commit `53fec90f`). The finished excision merges `develop` → `main`
  and is tagged on `main`; `.github/workflows/package.yml` triggers on
  `tags: ['v*']` and is branch-agnostic, so the tag's placement is a convention
  this plan relies on rather than something CI enforces.
- **Do NOT bump the version, create a tag, or push anything.** `CLAUDE.md` forbids `npm version`, `git tag`, `git push` and CI release triggers without the user explicitly saying "push"/"release"/"deploy"/"ship". This plan ends at a green working tree on a branch. The release itself is a separate, explicitly authorized act.
- **Retain the intelligence layer.** `src/intelligence/` and `src/main/intelligence-host/` stay. `agent-runtime` keeps its 7 `intelligence-host` imports and `ExternalRefreshScheduler.ts:6` keeps `recordPipelineRun`.
- **Retain `chat/providers/` as a subsystem.** Agents depend on it: `buildAgentContext.ts:15` imports `getProvider` from `../chat/providers/index`. Only the Power members are removed, not the registry.
- **The published set is `bin`, `.claude/skills`, `law`, `lib`, `models`, `package.json`, `README.md`, `LICENSE`, `THIRD_PARTY_LICENSES.md`.** `src/` is not published; `lib/` is its compiled bundle, so string literals in `src` DO ship. `law/` and `.claude/skills/` were measured clean of IW/Power and must stay clean.
- **Never both `npm install` and `npm run rebuild`.** Tests need better-sqlite3 built for system Node (`pretest` handles it); loading Local needs `npm run rebuild` back to Electron. Disclose which state the tree is left in.
- **Baseline with `npm test`, never `npx jest`** — the skipped `pretest` hook turns an ABI mismatch into ~868 phantom failures.
- **React 16 renderer.** No JSX, no hooks, class components, `React.createElement()`.
- **Removing a `z.enum` member is a validation change, not just a type change.** A user upgrading with `aiProvider: 'power'` already in storage must degrade gracefully, never crash.

- [ ] **Step 3: Implement the core**

Append to `scripts/publish-guard-core.js`, above `module.exports`:

```js
/**
 * Content half of the publish guard (v0.6.0).
 *
 * The path half above catches a forbidden FILE. It structurally cannot catch
 * WP Engine Intelligent Web or Power, because those compile into `lib/main.js`
 * alongside everything else — one allowed path carrying strings that must not
 * ship. Tool names and product names survive bundling verbatim (they are tool
 * ids and description text), so scanning the packed text is the check.
 *
 * Patterns are deliberately narrow. A guard with false positives gets deleted;
 * `powerful`, `AI-powered` and `superpowers` are all live in this codebase and
 * are pinned as must-survive in the suite.
 */
const FORBIDDEN_CONTENT = [
  {
    label: 'Intelligent Web MCP tool name',
    pattern: /\biw_(?:connect_site|disconnect_site|get_connection_status|fleet_status|list_kb_collections|get_kb_collection|search_kb)\b/,
  },
  { label: 'Intelligent Web product name', pattern: /Intelligent Web/ },
  { label: 'Hub Plugin product name', pattern: /Hub Plugin/ },
  { label: 'WP Engine Power inference endpoint', pattern: /api\.ai\.wpengine\.com/ },
  { label: 'WP Engine Power product name', pattern: /WP Engine Power/ },
];

/**
 * Given the packed files as {path, content}, return every rule hit.
 * Text-only: the caller is responsible for skipping binaries.
 */
function findForbiddenPublishContent(files) {
  if (!Array.isArray(files)) return [];
  const hits = [];
  for (const file of files) {
    if (!file || typeof file.content !== 'string') continue;
    for (const rule of FORBIDDEN_CONTENT) {
      if (rule.pattern.test(file.content)) {
        hits.push({ path: file.path, label: rule.label });
      }
    }
  }
  return hits;
}
```

Then change the export line to:

```js
module.exports = {
  findForbiddenPublishFiles,
  FORBIDDEN_SEGMENTS,
  findForbiddenPublishContent,
  FORBIDDEN_CONTENT,
};
```

Add this function, and call it from the guard's main body after the existing path check:

```js
// Extensions worth scanning. Everything npm publishes here that can carry a
// product string is text; models/*.onnx and images are skipped by omission
// rather than by a size heuristic, so a new binary type is skipped loudly
// (it simply is not scanned) instead of silently truncated.
const TEXT_EXT = new Set(['.js', '.mjs', '.cjs', '.json', '.md', '.ts', '.txt', '.html', '.css', '.map']);

function scanPackedContent() {
  const tmp = fs.mkdtempSync(path.join(os.tmpdir(), 'nexus-publish-guard-'));
  try {
    // `npm pack` writes the tarball to cwd and prints its filename.
    const out = execFileSync('npm', ['pack', '--json', '--ignore-scripts'], {
      encoding: 'utf8',
      stdio: ['ignore', 'pipe', 'inherit'],
    });
    const parsed = JSON.parse(out);
    const entry = Array.isArray(parsed) ? parsed[0] : parsed;
    const tgz = path.resolve(entry.filename);

    execFileSync('tar', ['-xzf', tgz, '-C', tmp], { stdio: 'inherit' });

    const files = [];
    const walk = (dir) => {
      for (const name of fs.readdirSync(dir)) {
        const full = path.join(dir, name);
        const st = fs.statSync(full);
        if (st.isDirectory()) { walk(full); continue; }
        if (!TEXT_EXT.has(path.extname(full))) continue;
        files.push({
          path: path.relative(tmp, full),
          content: fs.readFileSync(full, 'utf8'),
        });
      }
    };
    walk(tmp);

    fs.unlinkSync(tgz);
    return findForbiddenPublishContent(files);
  } finally {
    fs.rmSync(tmp, { recursive: true, force: true });
  }
}
```

And in the guard's main body, after the existing forbidden-path refusal:

```js
if (contentHits.length > 0) {

    console.error(`  ${hit.path}: ${hit.label}`);
  }
  console.error('\nThis package is PUBLIC on npm. Remove the surface or do not publish.\n');
  process.exit(1);
}
```
